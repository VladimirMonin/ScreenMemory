**P2 correction — raw receive-buffer wipe.** Reviewer P2: on a rejected or abandoned handshake receive the raw credential bytes were released before any wipe; only a delivered `Frame` was wiped (`fill(0)` in `Frame::drop`), so a malformed/truncated frame, invalid JSON/UTF-8, IO error or deadline/cancel left the bytes in freed memory. Fix: one private RAII owner `FrameBuffer` now holds the raw `Vec<u8>` **and** its shared-budget permit and wipes in `Drop` with `zeroize` (volatile write plus fence, which the optimizer may not delete the way it may delete `fill(0)`), i.e. on partial/truncated read, IO error, invalid UTF-8/JSON, handshake deadline, caller cancellation, and the ordinary drop after delivery; ownership transfers into `Frame` (`as_bytes` unchanged) with no relaxation of the budget or poison invariants (`vec![0; length]` is still allocated only after the permit, the permit is released on every error path, and an incomplete frame still poisons the reader). The outbound `CappedJson` wipe uses the same `zeroize` primitive, so no plain `fill(0)` wipe remains in the crate. Four synthetic canary regressions in `crates/framing` (private per-unit-test instrumentation records each wipe and asserts the bytes are all zero inside `Drop` while the allocation is still live; no freed memory is read and the canary is never printed) cover malformed/truncated/invalid-UTF-8 handshake reads, the deadline and caller cancellation on a partially received canary frame, and the delivered-frame drop, asserting budget return and reader poison on each path (the regression proves a per-path wipe before release; the non-elision guarantee comes from `zeroize`, not from a debug-build check). FRAMING is now 17 cases (12 transport integration + 5 lib unit, including the pre-existing allocation proof, whose payload-allocation counter is now per-test because more than one unit test allocates frames); the 8 native SESSION cases and all their behavior are unchanged. Dependency wiring: `zeroize` (workspace `=1.8.2`, as already used by application/credentials) added to `sm-framing` with the exact workspace dependency allowlist and `Cargo.lock` updated accordingly. Transient serde/allocator/OS copies (`IgnoredAny` parse, swap/crash dumps) remain an explicit `not claimed` limitation, not a wipe guarantee.

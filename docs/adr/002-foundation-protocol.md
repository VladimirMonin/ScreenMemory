# ADR-002 — Single-owner foundation API and Rust protocol seam

Status: **implemented partially in S01-T03a; host/transport acceptance pending**. Sources: master v3 §§4–5, S01 §§4–5 and T03. Does not amend nine source plans. See [bounded evidence](../progress/S01/t03a-contracts.md).

## Context and decision

A single future `shotd` must own application state; GUI/CLI/MCP will be clients, not writers. Initial Rust owner comprises `sm-domain` (canonical UUID identities and lossless decimal-string u64 revisions), `sm-protocol` (application/bridge v1.0 DTOs, typed error registry, Rust validators and draft 2020-12 schemas), `sm-application` (FoundationApi, FoundationControlApi and abstract repository/probe ports). No concrete host, storage, capture or SDK dependency. `RequestContext` and `Scope` are internal application types, not serde DTOs: host will derive them from authenticated peer credentials and never from `params` or `client_kind`.

Wire decisions: UUIDs lowercase hyphenated canonical; u64 revision decimal string 0..=u64::MAX; absent diagnostic optional field means unknown, explicit null is rejected; RFC3339 UTC with terminal `Z`; consent lifetime 1..300 seconds. Profile/build max 128, method max 96 (ASCII identifier alphabet); safe message max 512 Unicode scalar values, no control characters; unknown fields rejected in typed DTOs. `AppError.code` and bridge error/state are enums, not arbitrary strings. Responses are tagged `kind=result|error` with exclusive fields. Request envelope and `(method,params)` require **both** schema validation passes (`application-v1`, `application-methods-v1`); the former intentionally cannot validate method-specific params alone. Rust dispatch rejects unknown methods with `METHOD_NOT_SUPPORTED` without calling a handler. Application and bridge are independent version namespaces, initially 1.0, no automatic higher-minor acceptance.

New workspace retains donor Rust edition 2021 (not an edition migration); Rust toolchain is pinned to 1.98.1 MSVC. Schemars `=1.2.1` explicitly uses draft 2020-12. Generator only writes into a newly created explicit directory or compares in memory (`--check`); committed schemas include a standalone fixed `foundation-errors` registry. TypeScript generator and strict Ajv 2020-12 validation of both schemas belong to T03b, not to this proof. No version of this DTO/fixture is evidence of live ACL/handshake/framing, deduplication, scope enforcement, consent storage, policy epoch, cancellation or secure transport. These gates require host work and synthetic runtime checks in T05–T07. No fake-success operations for future search/capture.

Alternatives rejected: monolithic Inspector startup / SDK objects in DTOs; trusting the caller's declared kind; JavaScript number for u64 revision; permissive nullable response shape; silent fallback from unknown method. Future breaking wire changes require a new version, schema/fixture update and review. `request_shutdown` receipt acknowledges accepted stop, not process termination.

# ADR-006 — Shared bounded framed-byte transport

Status: S01-T06a candidate; S01 IN_PROGRESS. Sources: S01 §5.3/5.5, master §5.4. Nine source plans unchanged.

A separate `sm-framing` crate owns only async byte transport over generic Tokio `AsyncRead`/`AsyncWrite`. Wire: 4-byte little-endian nonzero `u32` length, followed by UTF-8 complete JSON (not newline-delimited). Trusted session owner selects `Handshake` (8 KiB) or `Application` (4 MiB); 3-second handshake **receive** deadline is absolute from `receive` invocation including budget wait. It is not the eventual end-to-end authentication deadline. Lexical string/escape-aware depth guard rejects depth >64 before `serde_json::Value` syntax/trailing-data check; this parse is bounded by frame length, but parsed AST is **not** covered by raw buffer permits.

One 16 MiB `BufferBudget` instance is passed/cloned across all host connections, read buffers and outbound writer paths. Reader checks prefix before payload allocation, acquires exact-length permit and retains it through frame lifetime; writer acquires a full phase-limit permit before capped streaming JSON serialization. A non-waiting `try_acquire_owned` admission gate limits each serialized writer to **8 total polled sends** (one active plus up to seven queued). Overflow returns typed `WRITER_QUEUE_FULL` before mutex, payload serialization, memory-budget reservation or wire writes; no suspended overflow producers inside the writer. Unpolled caller-owned futures are outside the internal queue and are not counted. A FIFO Tokio mutex serializes entire prefix/body/flush; admitted waiting callers hold no queued frames. RAII admission permits return on success, serialization/error, queued cancellation and active cancellation. Queued cancellation before first byte does not poison; cancellation/error after starting a write poisons the writer, causes all admitted waiters to refuse after lock acquisition and prevents another frame on a potentially partial stream. This limit is separate from the shared 16 MiB raw budget and future session caps of 16 clients/8 requests. Receive cancellation/error/timeouts poison the reader. The caller must discard the underlying transport; no automatic recovery/resync. Generic serde/IO messages, raw bytes and payloads are not emitted via ordinary error/Debug surfaces. `Frame::as_bytes` is explicitly available only for a future authenticated boundary.

This does **not** implement a pipe listener, Win32 peer ACL/session check, credential authentication, handshake version/library/capability negotiation, 16-client/8-request admission, method schemas, ID correlation, cancellation dispatch or host composition. Existing Rust DTO owner `sm-protocol` and separate application/bridge versions are unchanged. FRAMING synthetic tests verify byte-layer S01-IPC-01/02 only, not complete IPC cases. No claim about whole-process RSS, backend termination on timeout or production host security.

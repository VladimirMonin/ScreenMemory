# ADR-007 — Windows sealed named-pipe endpoint candidate

Status: S01-T06b candidate; S01 IN_PROGRESS. Source: S01 §5.3/5.4, §6.1/6.2. Nine source plans unchanged. Native boundary only; host/session authentication and application dispatch remain separate.

`sm-pipe` consumes an opened/pinned `sm-isolation::NamespaceLayout`. The byte endpoint name contains product/dev/test + protocol major prefix, session ID and a truncated SHA-256 of domain tag, namespace, native root volume/file identity and current logon SID. Neither root path nor SID is sent in name/log/error. Case/root aliases resolve to the same native file identity. A host composition owner must retain its root pins/lease across listener lifetime; endpoint construction itself does **not** acquire a HostLease.

## Sealed pool decision

One default DACL or broad user SID is forbidden. Native Windows feasibility under unique own Test names found subsequent server instances require more than bit 0x4 on the logon ACE when `PIPE_ACCESS_DUPLEX|WRITE_DAC` is requested: narrower tested bootstrap `0x00140007` failed instance 2 with Win32=5, while `0x0016019f` succeeds for all 16. A zero-rights `OWNER_RIGHTS` ACE suppresses implicit owner control without widening data access to other logon sessions. The explicit bootstrap descriptor is **current logon SID `0x0016019f` + OWNER_RIGHTS `0`**; the server requests WRITE_DAC on its own handles. Only after all 16 are created, change the DACL on each *own new pipe object*, then read back each actual DACL and require exactly the current logon SID ACE `0x00100083` (FILE_READ_DATA `1`, FILE_WRITE_DATA `2`, FILE_READ_ATTRIBUTES `0x80`, SYNCHRONIZE `0x100000`) plus OWNER_RIGHTS `0`, no extra ACE. On any failure, close the acquired own handles; no serving/publishing or permissive fallback. Production client opens explicit `0x00100083` via CreateFileW + Tokio owned-handle adoption, not `ClientOptions::open` (Tokio 1.53.1 converts read/write to GENERIC_READ/GENERIC_WRITE). Server first instance sets FIRST_PIPE_INSTANCE, all 16 byte-mode instances set REJECT_REMOTE_CLIENTS; no post-seal instance creation. Bounded 16-handle pool is the guard: on connection drop, `DisconnectNamedPipe` and return the same handle synchronously via max-16 channel; all checked-out handles remain live during reconnect. Native lost-slot/connect failure poisons future accept; no ACL relaxation/recreate. Connection count is OS pool occupancy, not a hidden unbounded queue. Tokio `connect` cancellation is tested. A single stale Win32=233 first-read completion was observed on a recycled handle after reconnect; only the *first read* on that known reused slot retries that exact error once before any bytes. A second error propagates to sm-framing; no frame/payload retries or generic IO resynchronization. The reader/writer lifecycle remains caller-owned.

The feasibility probe in private `.pi/temporary/t06b-probe-cc4d3e62/` recorded `CreateFile(mask 4)` success on a **client end** (GetNamedPipeInfo end flag 0); actual extra server `CreateNamedPipeW` while that client remains open fails Win32=5, and SetSecurityInfo from that client handle fails 5. This is observed behavior, not a claim that numeric client mask 4 creates server instances. Client mask 4 is never requested in production. Final DACL readback is two masks `[1048707,0]` on each of 16. Client `GENERIC_WRITE`, WRITE_DAC and WRITE_OWNER opens fail 5; 17th data client fails 231; after disconnect, own overlapped Connect gives 997 pending and reconnect succeeds with 15 other handles live. `GetNamedPipeHandleStateW` does **not** surface remote-rejection bit (observed readback bit 0), so that option is verified from explicit Tokio creation configuration rather than claimed OS readback; a real remote client negative is NOT_RUN.

OS peer uses GetNamedPipe*ProcessId/SessionId + open process token TokenUser and SE_GROUP_LOGON_ID SID, rechecking PID while retaining process handle. Client additionally compares QueryFullProcessImageNameW canonical path to fixed trusted composition-root executable path, never wire/CWD/PATH. No thread impersonation or await under a substituted token. The trusted image check limits accidental fake endpoint acceptance but is not code-signing or a sandbox; same-user/admin, executable replacement after launch, manipulated installed path, and real other-logon behavior need independent system gates. The descriptor's OWNER_RIGHTS zero prevents broad owner data/control grant by static ACE/readback and observed same-owner WRITE_DAC denial; actual different logon session S01-SEC-01 remains NOT_RUN. Credentials, auth handshake, version negotiation, 8-requests/session correlation/cancel, host.ready, GUI/CLI/bridge and application dispatch are NOT_IMPLEMENTED. A secure pipe alone is not a serving host.

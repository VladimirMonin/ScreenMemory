# ADR-008 — Authenticated native RPC session and shared application client

Status: **S01-T06c candidate; independent review pending**. Sources: S01 §§5.1–5.5, 6.3, 10; master §5.4; prior [ADR-002](002-foundation-protocol.md), [ADR-005](005-local-credentials.md), [ADR-006](006-framing.md), [ADR-007](007-native-pipe.md). No change to nine immutable source plans. Evidence: [S01-T06c](../progress/S01/t06c-session.md).

`sm-session` owns native host session and Rust application-client. Accepted `sm-pipe::Connection` has passed native peer PID/session/token checks; client `sm-pipe::open` checks the fixed configured trusted server image **before** reading the scoped credential. Host bootstrap selects validated library ID, host ID and explicitly enrolled `Authenticator`s under its exclusive lease; session never creates vault records or roots. Host supplies actual `FoundationApi`/`FoundationControlApi` and one shared host `BufferBudget`. Private Rust-only hello/welcome carry application v1.0 (not bridge version), required status/doctor/shutdown capabilities, expected library, host ID in welcome, fixed profile and transient credential bytes. No root path/inventory before authorization; no library switching based on hello. Fail closed on unsupported major/minor, library, capabilities and credential. 8 KiB handshake and absolute 3-second server/client deadline. `sm-framing` raw frame and serialized buffer contents are wiped on drop; `Secret`/verifier drop wipes memory. This does not claim OS/swap/crash-dump eradication; Rust serde deserialization may create temporary allocations on malformed input, bounded by handshake size.

Application request/response use **existing** `sm-protocol` DTO, method registry and error codes; schema and TS generation are unchanged. Strict typed params; authorization before handler; `RequestContext` derives principal/scopes from verifier, connection ID from host session, request/correlation IDs per invocation. `client_kind` is absent and rejected. Only status, ordinary doctor and request_shutdown call typed ports; optional runtime inventory and other known methods return METHOD_NOT_SUPPORTED after scope check. Unknown methods return METHOD_NOT_SUPPORTED. No fake production diagnostics or endpoint. Shutdown receipt means accepted stop request, not closed handles.

A dedicated bounded read pump avoids cancelling a partially polled framed reader while handlers finish; one frame queued and one potentially waiting for the queue, both charged to shared raw-byte budget. At most 8 active IDs, each held through writer terminal delivery; duplicate active ID returns INVALID_REQUEST if response capacity exists. At full admission, additional request/control requiring an error response closes **only that connection** instead of launching a ninth operation/unbounded error queue. Cancel only signals the matching ID in its own session; disconnect cancels waiting/aborts local tasks, not proof of backend stop. Writer has existing 8-send gate. Client has 8-call nonwaiting gate, correlated response reader, no automatic replay on disconnect or ambiguous shutdown. No host autostart, no UI, no database migration, no model/network calls.

Remaining gates: host/CLI real service composition and host.ready, explicit production first-run root policy, GUI, other actual logon, remote/restricted-token tests, S01 full stage acceptance. Native synthetic tests only exercise current own logon/session; no claim of OS isolation against malicious same-user processes.

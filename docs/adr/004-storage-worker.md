# ADR-004 — S01-T05b foundation SQLite worker

Статус: candidate, independent reviewer pending. Основа: 4d09c61b9909e355b7ec9f2ec86bdda51070a32e (принят T05a); master v3 §13.1, S01 §§6.3, 7.1–7.4, 9.5, T05. Девять исходных планов не изменяются; этот документ не является принятием полного host.

## Решение

- `HostLease` перемещается в `sm-storage::StorageWorker` (выделенный `std::thread`). Только в worker выполняется blocking `rusqlite`; application port async, bounded `sync_channel(32)` + one-shot reply. `try_send` не блокирует Tokio thread, overload/disconnect и deadline→`Unavailable`. `shutdown` подтверждает завершение только после закрытия connection, DB entry pins и lease; timeout не позволяет второму owner открывать DB при живом соединении. Thread завершает работу при закрытии всех senders, а не при закрытии GUI.
- `HostLease::database_entry` ограничивает файл ровно `data/library.sqlite3` и SQLite sidecars. Existing entries проверены через Win32 `OPEN_REPARSE_POINT`, file identity, number of links и удержаны без DELETE sharing на всё время connection. Пустой/foreign DB не переименовывается/не удаляется. Процессы same-user/admin, подменяющие новые entries между check/open, вне обещаний sandbox; будущая интеграция должна сохранять эти guardrails.
- `sm-application::storage::{FoundationRepository,SchemaSnapshot,StorageError}` выдаёт только snapshot и строго typed AI enabled bool; нет generic SQL/connection/raw path. Нет runtime endpoint, секретов, AI/model autostart; `library_settings` только два bool=false ключа foundation. Невалидный JSON/schema/settings отвергается. Позднее расширение settings требует versioned contract.
- `0001_foundation.sql` содержит только `library_meta`, `library_settings`; bootstrap `schema_migrations` отдельно в коде, но в одной транзакции с DDL, seed UUID и checksum migration row. SHA-256 по UTF-8 shipped SQL bytes. `schema_version=1`, `format_major=1`, строгая сверка schema/rows/UUID/checksum. Повторное открытие не меняет identity/seeds. **Происхождение before adoption:** отсутствие main file *и* всех sidecars под `HostLease` разрешает создать новый файл; если main уже существует, даже с нулём видимых объектов, `application_id=0`, пустым header, page/freelist=0 или после VACUUM, он не считается новым. На новом файле до WAL и migration transaction сохраняется internal `PRAGMA application_id=0x534D4631` (`SMF1`) в rollback-journal режиме с readback; только после этого переходят к WAL. Неудача до marker оставляет неопределённый файл и отказ при повторе без repair/delete; ошибка migration rollback оставляет owned marker и нулевую схему либо корректную пустую bootstrap table, которые можно безопасно повторить. Existing main сначала проходит raw header marker gate **до SQLite-open**, затем SQLite read-only preflight c live WAL проверяет readback marker, user_version и строгое состояние: owned interrupted init или полностью валидная schema. Foreign/mismatched DB не получают marker и writer pragmas; при отсутствии marker отказ не создаёт WAL/SHM/journal. Marker сам по себе не доказывает валидность schema и не является sandbox/auth против намеренной подделки same-user/admin. Значение новое для ещё не принятого candidate; прежние unmarked candidate DB не имеют обещания compatibility и не присваиваются автоматически. Read-only preflight видит настоящий WAL, не `immutable=1`; для уже marked, но испорченной DB SQLite может взаимодействовать с существующими sidecars, поэтому без repair/delete. Неизвестная версия / checksum / schema mismatch — отказ.
- Действительные `journal_mode=WAL`, `foreign_keys=ON`, `synchronous=FULL`, `busy_timeout=5000` сверяются на writer connection. `rusqlite=0.37.0` `bundled` и транзитивная `libsqlite3-sys=0.35.0` закреплены Cargo.lock. `sqlite_version()` — runtime evidence, но FTS/vec actual queries, sqlite-vec registration/ABI — S01-T09; arbitrary `load_extension` не вводится. Единственная точка будущей статической owner registration — worker до открытия connection, после отдельного решения T09.

## Ограничения и дальнейший владелец

S01-T05b не реализует shotd bootstrap, secure IPC/listener, credential store, GUI, CLI, bridge, capture, backup/restore S08, реальные upgrades старой product schema и host.ready. Деструктивная миграция без проверенного backup всегда отклоняется; из этого не следует готовность backup платформы. Локальный NTFS и синтетические временные DB — единственный runtime proof этого среза. Windows ACL refusal без изменения ACL/глобальных прав NOT_RUN; owned exclusive-sharing denial проверяется отдельно и не называется ACL. Тестовый fault перед commit существует только под `#[cfg(test)]` и не создаёт production bypass.

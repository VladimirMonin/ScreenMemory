# ADR-005 — Local credential store and host principal policy

Status: **S01-T05c candidate, reviewer pending**. Source S01 §5.4; master §4.4 and §5.4. Nine source plans unchanged. This decision does not implement a pipe listener, OS peer/session ACL, S07 token provisioning, consent lifecycle or SDK bridge.

`sm-application::credentials` owns a platform-neutral `SecretStore` port, typed `(environment, library_id, profile)` identity and host policy. `sm-credentials` implements it via Windows Credential Manager generic credentials (`CredReadW`, `CredWriteW`, exact `CredDeleteW` only inside the unit test), never via environment, plaintext settings or DPAPI files. Namespace is one of `ScreenMemory.V1`, `.Dev.V1`, `.Test.V1` from the existing isolation owner; profile is fixed owner or synthetic Test-only read-only. The provided `LibraryId` must come from the already validated library metadata when the host is built; the current standalone seam has no bootstrap, and does not itself authenticate a library root. An arbitrary target string is never an input. No enumeration or foreign key lookup.

Explicit owner enrollment under future exclusive `HostLease` generates versioned 32-byte cryptographic random payload, retains already-valid existing bytes, rejects corrupted version/size and store failure with `CredentialStoreUnavailable`. `open` never provisions; `authenticate` never provisions. Verifier is SHA-256 of 33-byte versioned secret kept in memory; SHA-256 preimage relies on 256-bit randomness. Comparison uses `subtle::ConstantTimeEq` on equal-length digest; length/version rejection occurs before hashing. Secret buffers and verifier zeroize on drop; Credential Manager result blob is cleared before `CredFree` within documented max blob bounds, local write buffer is cleared after `CredWriteW`. OS storage, process memory copies, swap, same-user malicious code, and incidental crash dumps remain outside this mitigation. Secret is not `Debug`, `Display` or `Serialize`. Safe error codes contain no provider errors or secret bytes.

`RequestContext` is only produced by this policy after library/credential check in the private test boundary; `client_kind` does not enter policy. Owner scopes are fixed; TestReadOnly receives only ReadStatus/RunDoctor. `authorize` checks scope before invoking a privileged callback. The existing public `RequestContext::from_authenticated_peer` remains a host-only convention, not a transport security gate; future host composition must not expose it to untrusted inputs. OS peer/session ACL, framing, handshake and dispatch gate still require separate T05/T06 implementation and negative tests. Consent/probe lifecycle remains later owner.

`CredWriteW` has no create-if-absent primitive. Adapter does exact-target `CredReadW` collision refusal before write and verifies readback. Future host must serialize enrollment under `HostLease`; concurrent external same-user vault writers cannot be excluded or sandboxed. A readback mismatch fails closed but cannot undo external vault mutation automatically. Unit test creates unique cryptographic UUID test target and deletes only its own successfully enrolled key; collision with an existing target must never be deleted. Full principal/ACL/session security is not claimed by this candidate.

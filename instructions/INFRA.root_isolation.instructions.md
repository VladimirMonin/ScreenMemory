# INFRA — Root isolation до host

`sm-isolation` — единственный текущий владелец identity продукта/окружения и read-only Windows resolver. Installed configuration явно содержит существующие четыре каталога `ScreenMemory[.Dev|.Test]/{data,config,cache,webview}` и явно известные forbidden donor roots; test требует explicit root с четырьмя заранее созданными дочерними каталогами. Ни CWD, ни home, ни PATH не используются как fallback. Не считывать реальные settings/history/credentials Inspector для поиска donor roots. Если известный forbidden root не разрешается, отказ, не исключение из проверки. Никаких изменений существующих папок resolver не делает.

`HostLease::acquire` потребляет `NamespaceLayout` с удерживаемыми root/ancestor handles и открывает постоянный `data/host.lock` с немедленным exclusive byte-range OS lock до любых будущих SQLite writes. Locked handle закрывается раньше pinned root chain; guard не Clone, при drop lock-файл не удаляется и содержимое не интерпретируется как PID. Busy не даёт права kill/recover чужой host; отсутствие IPC не снимает OS lock. Resolver сам по себе не выдаёт разрешения на SQLite writes, не создаёт каталогов и не очищает непустые данные. Migration preflight/backup/DB/lifecycle ещё не реализованы. Канон и принятый staging — protected source of truth; test roots — только `.pi/temporary` со строго синтетическими sentinel bytes, cleanup только собственной fixture после её проверок. Не распространять test cleanup на живой каталог, не обещать физическое удаление на SSD. Backup/integrity/hash/restore policy для persistent data определит будущий storage owner до первой записи; отсутствие проверенного backup означает отказ в потенциально разрушительной миграции. Никаких автозапусков updater, donor shell или чужих сервисов.

`windows.rs` изолирует Win32 SDK ABI: local fixed NTFS, каждый ancestor и leaf открываются с `FILE_LIST_DIRECTORY|FILE_READ_ATTRIBUTES`, `OPEN_REPARSE_POINT|BACKUP_SEMANTICS`, без FILE_SHARE_DELETE, удерживаются на lifetime layout/lease; metadata-only `FILE_READ_ATTRIBUTES` **не удерживает rename** (synthetic RED T05a), поэтому менять access обратно нельзя; после закрепления всей цепочки повторная проверка каждого prefix по volume/file identity отвергает initial swap. Конфликт с уже открытым DELETE handle отвергается. `host.lock` открывается внутри удерживаемого root с `OPEN_REPARSE_POINT` и без DELETE share, rejects directory/reparse/multi-hardlink, не unlink/truncate. Эта проверенная на synthetic NTFS комбинация защищает от обычных rename/reparse races, **не** sandbox против процесса того же пользователя/admin и не разрешение на произвольные path-based writes внутри root. Directory identity и полный путь внутренние, не DTO/status/обычные логи. Diagnostics — только typed `SafeEvent` и bounded safe code. Junction и symlink различать: непривилегированный junction proof обязателен, symlink может дать точный NOT_RUN с raw OS code без elevation/Developer Mode/ACL changes. Проверки: `scripts/verify.ps1`, `scripts/verify-contracts.ps1` после обновления workspace boundary, raw exits и source/plan integrity сохраняются. Политика/ограничения: [ADR-003](../docs/adr/003-root-isolation.md).
